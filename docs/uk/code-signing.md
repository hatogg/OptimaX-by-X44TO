## Політика підпису коду

Файли OptimaX для Windows (інсталятор, портативна версія й сам `OptimaX.exe`) підписуються безкоштовним підписом коду від [SignPath.io](https://signpath.io), сертифікат — від [SignPath Foundation](https://signpath.org). Підписані релізи починаються з першого релізу після схвалення заявки SignPath Foundation; раніші релізи не підписані — для них є `SHA256SUMS.txt`.

- **Що підписується.** Лише файли, які зібрав GitHub Actions з цього репозиторію (`.github/workflows/release.yml`): спершу `OptimaX.exe` і портативна версія, потім інсталятор, у якому вже підписаний `OptimaX.exe`. Файли, зібрані будь-де інакше, не підписуються.
- **Кожен підпис схвалюється вручну** в SignPath, окремо для кожного релізу.
- **Ролі:**
  - автори (мають право змінювати код): [X44TO (@hatogg)](https://github.com/hatogg);
  - рецензенти (перевіряють зміни від інших людей перед злиттям): [X44TO (@hatogg)](https://github.com/hatogg);
  - схвалює підпис: [X44TO (@hatogg)](https://github.com/hatogg).
- Зміни від інших людей потрапляють у код лише через pull request після рецензії.
- Вхід у GitHub і SignPath — з двофакторною автентифікацією.

## Приватність

OptimaX не збирає й не надсилає персональних даних і телеметрії. Програма звертається до мережі лише для своїх функцій:

| Що | Куди | Коли |
| --- | --- | --- |
| Перевірка оновлень | `api.github.com` — список релізів цього репозиторію | Під час запуску й не частіше ніж раз на 6 годин |
| Завантаження інструментів | GitHub (PresentMon, Mesa і DXVK для майнінгових карт), winget, списки блокування реклами | Лише коли ви натискаєте відповідну кнопку або вмикаєте функцію |
| Тести мережі | DNS-сервери (Cloudflare, Google, Quad9, AdGuard, OpenDNS), `speed.cloudflare.com`, регіони дата-центрів | Лише коли ви запускаєте тест |
| Аналіз дампів | Сервер символів Microsoft `msdl.microsoft.com` | Лише під час аналізу дампу, якщо встановлено Debugging Tools for Windows |
| Монітор на телефоні | Сервер лише у вашій домашній мережі | Лише коли ви його вмикаєте |
| Звіт про помилку | Сторінка нового issue на GitHub у браузері | Лише коли ви самі натискаєте «Надіслати»: ви бачите весь текст, ім'я користувача й шляхи профілю з нього прибрано |

Усі зміни системи OptimaX показує до застосування, записує в журнал і вміє повернути; програму можна видалити через «Програми й засоби» Windows.

## Як увімкнути підпис (для власника репозиторію)

1. Увімкнути двофакторну автентифікацію в GitHub.
2. Подати заявку SignPath Foundation на безкоштовний підпис для відкритого коду ([умови](https://signpath.org/terms)) і дочекатися схвалення.
3. У SignPath створити проєкт `OptimaX`, підключити GitHub як довірену систему збірки й додати дві конфігурації артефактів зі слагами `app` і `installer` — їхній вміст лежить у [`.signpath/artifact-configurations`](../../.signpath/artifact-configurations). Політика підпису — `release-signing` з ручним схваленням.
4. У GitHub → Settings → Secrets and variables → Actions додати змінну `SIGNPATH_ORGANIZATION_ID` і секрет `SIGNPATH_API_TOKEN` (інші слаги — змінними `SIGNPATH_PROJECT_SLUG` і `SIGNPATH_POLICY_SLUG`, якщо вони не стандартні).
5. Запустити реліз як завжди: job «Code signing (SignPath)» надішле два запити, і кожен треба схвалити в SignPath (job чекає до 3 годин). Без змінної `SIGNPATH_ORGANIZATION_ID` реліз виходить, як і раніше, без підпису.
